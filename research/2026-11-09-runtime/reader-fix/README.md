# Single-channel OME-TIFF page-axis correction

The first optimized MIP mock entry was accepted for reception, then failed before inference because its input was reported as `IYX/(28,2048,2048)`. The original reader rejected that page-axis representation. This correction accepts IYX only when OME declares one time point, one channel, and a matching z depth. Modality, physical spacing, finite-value checks, model architecture, five weights and prediction functions are retained.

Real synthetic OME-TIFFs reproduced the rejection without reading protected mock pixels or ground truths. The actual CPU image passed three valid and four rejection cases. An offline container HTTP comparison reproduced old health200/invoke500 and corrected health200/invoke201 with four outputs. Managed RTX 3090 job1052 compared BF, PC and DIC inputs of 28x2048x2048: all output bytes matched the original prediction path. The independent review checked source drift, new TIFF fixtures and ambiguous metadata. These tests establish the scoped local correction; the actual official input header was not inspected.

`inference.py` is the corrected selected adapter, SHA-256 `019be8bc00d2e6af0b2aa95e65ae255c70a24d300db1f6b9bf29d6bd148641d7`. Its built image is `sha256:163d236171db0dea3c7332096c6592fa1cada9f253b1674f3d531d1d3c60ab9c`. The Dockerfile overlays the previous streaming image, whose build instructions are one directory above. The test scripts preserve exact executed source and server-path assumptions for audit; configure their project paths to reproduce elsewhere. They contain no data or model fitting.

An additional preregistered managed GPU check (job1054) covered six real synthetic IYX TIFFs of 28x2048x2048: uint8 and uint16, each with random full-range, constant-zero and constant-maximum values. All predictions were finite and byte-identical between the original and corrected computation. Each of the four serialized OME-TIFF outputs matched its prediction bytes, shape and physical spacing. `DTYPE_OUTPUT_RECEIPT.json` and `dtype_gpu_check.py` preserve the results and exact executed test source. This is integer-input/output robustness evidence, without ground truths or model fitting.
